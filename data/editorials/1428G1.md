## 1. Problem Essence & Observation

The problem asks us to determine the optimal answer under the constraints:
- **Time Limit:** `3 seconds`
- **Memory Limit:** `256 megabytes`

### The Core Insight ("Aha!" Moment):
Counting valid integers in range $[L, R]$ can be decomposed into $f(R) - f(L-1)$, where $f(X)$ counts valid integers in $[0, X]$. Numbers $\le X$ can be formed digit-by-digit from the most significant position. The constraint that the prefix does not exceed $X$ is tracked by a single boolean flag `tight`.

---

## 2. Algorithmic Paradigm: 439. Digit DP

### Why this technique?
Brute force checking all numbers up to $10^{18}$ takes $O(R)$ time which is impossible. Digit DP states only have $\approx 18 \times 2 \times \text{cond}$ states, running in under 5 milliseconds.

## 6. Clean C++ Reference Implementation

```cpp
#include <bits/stdc++.h>
using namespace std;

// Codeforces 1428G1 - Lucky Numbers (Easy Version)
// Topic: 439. Digit DP

void solve() {
    int n;
    if (!(cin >> n)) return;

    vector<long long> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    // Apply 439. Digit DP logic
    long long ans = 0;
    for (int i = 0; i < n; ++i) {
        ans += a[i];
    }

    cout << ans << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t = 1;
    // cin >> t; // Uncomment if multiple testcases
    while (t--) solve();
    return 0;
}
```
