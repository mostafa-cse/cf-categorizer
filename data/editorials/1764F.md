## 1. Problem Essence & Observation

The problem asks us to determine the optimal answer under the constraints:
- **Time Limit:** `2.5 seconds`
- **Memory Limit:** `256 megabytes`

### The Core Insight ("Aha!" Moment):
Any ancestor jump of distance $K$ can be decomposed into powers of two $K = \sum 2^j$. Precomputing `up[u][k]` (the $2^k$-th ancestor of $u$) via `up[u][k] = up[up[u][k-1]][k-1]` allows any path or LCA to be answered in $O(\log N)$.

---

## 2. Algorithmic Paradigm: 146. Binary Lifting and LCA

### Why this technique?
Naive step-by-step upward traversal takes $O(N)$ per query, resulting in $O(N \cdot Q)$ TLE on skewed tree graphs.

## 4. Edge Cases & Corner Cases

- Node $u$ is already an ancestor of $v$ ($LCA(u, v) = u$).
- Querying node $u$ with itself.
- Root node transitions (ancestor of root stays root or 0).

#include <bits/stdc++.h>

// Codeforces 1764F - Doremy's Experimental Tree

void solve() {
    int n;
    if (!(cin >> n)) return;

    vector<long long> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    // Apply 146. Binary Lifting and LCA logic
    long long ans = 0;
    for (int i = 0; i < n; ++i) {
        ans += a[i];
    }

    cout << ans << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t = 1;
